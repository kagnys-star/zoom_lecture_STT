# ZoomCaption

Zoom 수업 오디오를 **실시간 한국어 자막**으로 옮기고, 고치고, 저장하고, 요약하는 macOS 로컬 도구.
음성이 기기 밖으로 나가지 않습니다 — 전사와 요약 모두 온디바이스입니다.

- 전사: `SpeechAnalyzer` / `SpeechTranscriber` (macOS 26 내장, ko-KR)
- 오디오: Core Audio process tap — 가상 오디오 드라이버(BlackHole 등) 설치 불필요
- 요약: 로컬 Ollama 모델(권장) → Apple Intelligence → 추출식 순으로 폴백. 전부 기기 안에서 돕니다
- 교안 용어: `mecab-ko` 형태소 분석. 없으면 내장 규칙으로 폴백
- UI: `localhost` 웹 페이지

## 설치

```bash
./setup.sh
```

시스템 조건을 확인하고, `mecab-ko`·`mecab-ko-dic`과 Ollama를 설치하고, 앱을 빌드합니다.
메모리에 맞는 요약 모델(16GB → `qwen3:8b`)을 안내하니 `ollama pull` 로 받아주세요.
끝나면 안내에 따라 **시스템 오디오 권한**과 **Apple Intelligence**를 켜주세요.

요구 사항: macOS 26 이상, Apple Silicon, Command Line Tools(`xcode-select --install`).

## 실행

```bash
open ZoomCaption.app
```

브라우저가 `http://127.0.0.1:8765` 로 열립니다. Dock에 뜨지 않고 백그라운드에서 돕니다.

**끄는 법은 오른쪽 위 `⏻ 완전 종료` 버튼입니다.** 브라우저 탭만 닫으면 앱은 계속 돌아갑니다
(수업 중에 창을 잘못 닫아도 녹음이 이어지도록 일부러 그렇게 만들었습니다).
완전 종료를 누르면 기록을 저장하고 앱이 꺼진 뒤, **정말 꺼졌는지 확인해서** 알려 줍니다.
혹시 안 꺼지면 8초 뒤 강제로 끝내고, 그래도 남아 있으면 화면에 `pkill -f ZoomCaption.app` 을 띄웁니다.

### 첫 실행 시 권한 (필수)

**시스템 설정 → 개인정보 보호 및 보안 → 화면 및 시스템 오디오 기록** 에서 ZoomCaption을 켜세요.
권한이 없으면 macOS는 오류 대신 **무음**을 흘려보내기 때문에 자막이 한 줄도 안 생깁니다.
앱이 이 상태를 감지하면 웹 UI에 경고를 띄웁니다.

> 애드혹 서명이라 다시 빌드하면 권한을 다시 켜야 할 수 있습니다.

## 기능

### 자막 편집

**편집** 버튼을 누르면 편집 모드가 켜집니다.

- 줄을 클릭해 텍스트를 고칩니다. `Enter` 저장, `Esc` 취소. 고친 줄에는 ✎ 표시가 붙습니다.
- 각 줄의 ✕ 로 한 줄 삭제.
- 체크박스로 여러 줄 선택 후 **선택 삭제**. `Shift+클릭` 으로 구간 선택.
- 텍스트를 비우고 저장하면 그 줄이 삭제됩니다.

모든 편집은 **즉시 디스크에 저장**됩니다. 녹음 중에도 편집할 수 있습니다.

### 자막 지연

`SpeechTranscriber` 의 `ReportingOption.fastResults` 를 켭니다. 이걸 빼면 **첫 자막이 뜨기까지
10.2초**를 기다립니다(3회 측정 모두 10.22~10.23초로 일정). 켜면 **0.6~1.5초**로 떨어지고,
갱신 간격 최대치도 11초 → 3.4~5.8초로 줄어듭니다.

같은 WAV 를 `--selftest` 로 넣어 확정 자막을 비교하면 **글자 단위로 동일**했습니다
(신뢰도 0.68 vs 0.69). 지연만 줄고 결과는 그대로입니다. 정확도가 더 중요하면
`ZOOMCAPTION_FAST_RESULTS=0` 으로 끌 수 있습니다.

> 합성음 한 샘플로 확인한 결과입니다. 실제 강의 소리에서는 다를 수 있습니다.

### 받아쓰는 중 / 확정된 자막

화면 아래 **받아쓰는 중** 칸은 아직 확정되지 않은 텍스트입니다. 말이 끝나 문장이 확정되면
그 줄은 위쪽 자막 목록으로 올라가고 아래 칸은 비워집니다. 두 영역은 서로 다른 칸이라
겹치지 않고, 스크롤도 따로 움직입니다. 편집·삭제·검색은 **확정된 줄에만** 적용됩니다.

### 창을 닫아도 녹음은 계속됩니다

녹음은 앱(백그라운드 프로세스)이 하고, 웹 UI는 그걸 들여다보는 창일 뿐입니다.
브라우저 탭을 닫아도 받아쓰기는 멈추지 않습니다. **정지를 눌러야** 끝나고 저장됩니다.

그래서 나중에 창을 다시 열면 이미 녹음이 돌고 있는 상태로 보입니다. 저절로 켜진 게 아니라
아까부터 돌고 있던 겁니다. 헷갈리지 않도록 창을 열 때 노란 띠로 알려 주고,
경과 시간도 0부터 다시 세지 않고 실제 시작 시각에서 이어 셉니다.

### 두 전사기를 나란히

화면이 위아래 두 칸입니다.

| | 엔진 | 성격 | 표시 |
|---|---|---|---|
| **위 (정식 기록)** | Whisper large-v3-turbo | 정확. 30~60초 뒤따라옴 | 전체 |
| **아래 (실시간)** | SpeechTranscriber | 즉시(0.6초). 부정확 | **최근 1분만** |

아래 칸을 1분으로 자르는 건 화면 표시만입니다 — **저장은 양쪽 다 전부** 합니다
(`transcript.md` = Whisper, `transcript_live.md` = 실시간). 90분치를 DOM 에 쌓아두면
줄마다 렌더 비용이 붙어 실시간이 다시 끊기고, 아래 칸은 어차피 위 칸이 곧 덮어쓸
"지금 무슨 말이 나오나" 용도라 오래 남길 이유가 없습니다.

편집·삭제·검색·요약·내보내기는 모두 **위 칸(Whisper)** 을 대상으로 합니다.

위 칸이 비어 있으면 **왜 비었는지 그 자리에 띄웁니다** — 소리 저장이 꺼져 있거나,
whisper 가 설치되지 않았거나, 소리 파일을 만들지 못한 경우입니다.
조용히 비어 있으면 기다리기만 하다 수업을 통째로 놓치게 됩니다.

### Whisper 재전사

**Whisper 는 수업이 도는 동안 뒤에서 함께 돕니다.** 30초짜리 조각이 모일 때마다
(경계에서 단어가 잘리지 않게 2초씩 겹쳐서) 한 번에 하나씩 전사합니다.
실시간의 27배라 듀티 사이클이 4% 남짓이고, **정지를 누르면 재전사가 이미 끝나 있습니다.**

조각을 동시에 여러 개 돌리지 않는 이유는, whisper.cpp 가 Metal 위에서 GPU 바운드라
프로세스를 늘려도 GPU 를 시분할할 뿐 총 시간은 그대로인데 메모리만 547MB 씩 늘기 때문입니다.
`-p N` 으로 오디오를 나누는 방식은 분할점마다 문맥이 끊겨 정확도까지 깎입니다.

교안 용어는 Whisper 의 initial prompt 로 들어갑니다.

M5 실측 — **30초에 1.1초, 실시간의 27배.** 2시간 강의 전체가 약 5분입니다.
`large-v3-turbo` 가 `medium` 보다 빠르면서 더 정확해서 그쪽을 씁니다.

같은 오디오를 넣은 정면 비교입니다.

| | 결과 |
|---|---|
| SpeechTranscriber | 예외 처리는 **드라이캐치 블로그를** 합니다 … **행자** 그러니까 생성자라는 것은 |
| Whisper turbo | 예외 처리는 **트라이케치 블록으로** 합니다 … **생성자** 그러니까 어떻게 보면 생성자라는 것은 |

**조용한 구간은 Whisper 에 넘기지 않습니다.** 무음은 Whisper 학습 분포 밖이라 없는 말을
지어냅니다 — 실측에서 조용한 30초에 "자막 제공 및 광고를 포함하고 있습니다" 를 뱉었습니다.
피크가 −42 dBFS 아래면 그 조각은 건너뜁니다.

> Whisper 자막에는 **소리 저장**이 켜져 있어야 합니다(설정, 기본 켜짐).
> 꺼져 있거나 whisper 가 없으면 위 칸에 그 이유를 띄웁니다.

### 소리가 안 들어올 때

**Zoom 소리를 잡습니다.** 시작할 때 Zoom 이 오디오 세션을 쥐고 있으면 Zoom 만,
아니면 시스템 전체로 자동 전환됩니다. 마이크는 기록하지 않습니다.

20초 넘게 아무 소리도 안 들어오면 자막 위에 빨간 띠로 알립니다. 원인이 둘인데
대처가 정반대라 구분해서 보여 줍니다.

- **Zoom 이 소리를 내는데 안 잡힘** → 권한 문제. 시스템 설정에서 켜세요
- **Zoom 이 조용함** → 회의에 들어가 발표자가 말하는 중인지 확인하세요.
  이때 다른 앱이 소리를 내고 있으면 그 앱 이름을 같이 보여 줍니다(그 소리는 잡히지 않습니다)

### 화면과 서버가 어긋나지 않게

브라우저 창은 서버가 쏘는 이벤트로 갱신됩니다. 그런데 연결이 끊기면(맥 절전, 앱 재시작)
**끊긴 사이의 이벤트는 그냥 사라집니다.** 그러면 화면은 조용히 굳은 채 자기가 굳은 줄도 모릅니다.

SSE 규격의 재전송 장치를 그대로 씁니다.

- 서버가 모든 확정 이벤트에 `id: <세대>-<번호>` 를 붙입니다
- 브라우저는 재연결할 때 `Last-Event-ID` 로 마지막 번호를 보냅니다
- 서버는 **그다음 것부터 다시 흘려줍니다** (최근 2000개 보관)
- 세대가 다르거나(앱 재시작) 보관함 밖이면 그때만 전체를 다시 받습니다

받아쓰는 중인 글자(`volatile`)는 보관하지 않습니다 — 초당 여러 번 나오고 나중에 다시
보내봐야 의미가 없어서, 보관함만 밀어냅니다.

복구할 때도 **통째로 다시 그리지 않습니다.** id 기준으로 없는 것만 넣고, 사라진 것만 빼고,
바뀐 것만 고칩니다. 그래서 스크롤이 튀지 않고, 편집 중이던 줄이 살아남고, 90분치가 쌓여도
멈추지 않습니다. 안전망으로 1분에 한 번 `/api/sync`(개수만, 수백 바이트)로 대조합니다.

헤더의 상태 알약에 연결 표시가 있습니다 — 초록이면 붙어 있고, 빨갛게 깜빡이면 끊긴 겁니다.

### 대조 — 두 기록이 어디서 갈리나

**대조** 탭에서 실시간 기록과 Whisper 기록을 **글자 단위로** 맞춰 봅니다.
세그먼트 경계로는 못 맞춥니다 — 실측에서 실시간은 줄당 14.1초, Whisper 는 4.8초라
경계가 아예 다릅니다. 그래서 텍스트를 이어 붙여 긴 일치 구간을 앵커로 잡고 정렬합니다.

실제 강의 600초로 재보면 **72% 가 일치**하고, 갈리는 부분은 세 갈래로 나뉩니다.

| 갈래 | 비중 | 예시 | 어떻게 볼 것인가 |
|---|---|---|---|
| **표기** | 33% | `해시맵`↔`hashmap`, `리스트`↔`list` | 같은 말인데 표기만 다름. Whisper 쪽이 맞음(영문 식별자 24종 대 0종) |
| **누락** | 19% | 한쪽에만 있는 구간 | 두 엔진이 상보적인 지점. 있는 쪽을 취하면 정보가 순증 |
| **다름** | 48% | `입니다`↔`에요`, `권고`↔`공부` | 대부분 뜻이 같은 어미 변형. 손대면 오히려 손해 |

두 기록의 시각은 거의 완벽히 겹칩니다(겹침 비율 중앙값 1.00, 안 겹치는 줄 0개).
그래서 갈리는 지점마다 시각이 정확히 찍혀 원문을 바로 찾아갈 수 있습니다.

### 정답지 — 어느 쪽이 나은지 숫자로

합치는 작업의 기준선은 "실시간보다 낫다" 가 아니라 **"Whisper 단독보다 낫다"** 입니다.
Whisper 가 이미 크게 앞서 있어서, 잘못 합치면 오히려 나빠집니다.
그걸 판별하려면 손으로 고친 정답지가 있어야 합니다.

**대조 → 정답지** 에서 구간(기본 5분)을 정하고 **초안 만들기** 를 누르면 Whisper 결과가
깔립니다. 소리를 들으면서 틀린 곳만 고친 뒤 저장하면, 실시간과 Whisper 의
**글자 오류율(CER)** 이 나옵니다. 한국어는 띄어쓰기가 불안정해 단어 단위(WER)보다
글자 단위가 맞습니다.

> **초안을 그대로 저장하면 안 됩니다.** Whisper 결과를 그대로 정답지로 삼으면
> Whisper CER 이 0% 로 나오는 순환이 됩니다. 반드시 들으면서 고쳐야 의미가 있습니다.

### 세션 폴더

수업 하나가 폴더 하나입니다. 기본 위치는 `~/Documents/ZoomCaption/`.

```
머신러닝-3주차/
├── session.json     ← 원본 (편집 이력·용어·요약 포함). 이어 적기가 이 파일을 읽습니다
├── transcript.md    ← 요약 + 전체 기록
├── transcript.srt   ← 자막 파일
└── 교안.pdf         ← 올린 교안 사본
```

**설정** 탭에서 두 가지를 따로 정합니다.

- **저장 위치** — **폴더 선택…** 으로 고릅니다. 이 폴더 *안에* 수업 폴더가 새로 만들어집니다.
  고른 폴더에 파일이 바로 쌓이지 않습니다.
- **수업 폴더 이름** — 비우면 `날짜_제목` 으로 자동 생성됩니다.
  같은 이름이 이미 있으면 `이름 (2)` 로 만들어 기존 기록을 덮어쓰지 않습니다.

### 이어 적기

**세션** 탭에서 저장된 수업의 **이어 적기** 를 누르면 그 기록을 불러와 뒤에 이어서 적습니다.

이어 적을 때 알아둘 것:

- **타임스탬프는 이어붙습니다.** 기존 기록이 40분이면 새 발화는 40분 02초부터 시작합니다.
  실제 시계 시각이 아니라 "이 수업 기록에서의 누적 위치"입니다.
  그래서 **SRT를 특정 녹화 영상에 물릴 생각이라면 이어 적기를 쓰면 안 됩니다** —
  자막 시각과 영상 시각이 어긋납니다. 그 경우엔 회차마다 새 세션으로 만드세요.
- 고쳐 둔 문장, 지운 줄, 교안 용어는 그대로 승계됩니다.
- 요약은 승계되지만 **새 내용은 반영되지 않은 상태**입니다. 이어 적기가 끝나면
  **요약 다시 생성** 을 눌러 전체를 다시 요약하세요.
- **앞서 저장한 요약 파일들은 요약 탭에 목록으로 남습니다.** 세션 안에는 마지막 요약
  하나만 들어 있어서, 1교시·2교시로 나눠 저장했다면 앞의 것은 파일로만 존재합니다.
  목록에서 **열기** 를 누르면 다시 불러옵니다.
- 이어 적기 기준 시각은 **실시간 자막과 Whisper 중 더 뒤까지 간 쪽**으로 잡습니다.
  한쪽만 보면 새 녹음이 기존 기록 위에 겹쳐 앉습니다 — 실측에서 실시간이 300초에서
  끊겼는데 Whisper 는 1200초까지 간 적이 있습니다. 소리 파일 이름(`audio_001202.wav`)도
  같은 기준이라 자막 시각에서 소리 위치를 그대로 찾을 수 있습니다.
- `transcript.md` / `.srt` 는 **덮어써집니다.** 회차별로 따로 남기고 싶으면
  이어 적기 대신 새 세션을 만드세요.
- 녹음 중에는 다른 세션을 열 수 없습니다.

### 교안 PDF

**교안** 탭에 PDF를 끌어다 놓으면 용어를 뽑아 두 곳에 씁니다.

1. 음성 인식 힌트 (`AnalysisContext.contextualStrings`, 상위 150개) — 용어를 직접 입력할 필요 없이 교안에서 자동으로 뽑습니다
2. 요약 프롬프트의 용어집 (상위 40개) — 인식 오탈자를 올바른 용어로 되돌립니다

용어는 3단계로 추립니다.

1. **mecab-ko 로 명사구 추출** — 조사·어미를 떼고 복합명사를 잡습니다.
2. **페이지 분포로 거르기** — 서로 다른 용어 3개 이상이 *정확히 같은 페이지 집합*에 나오면서
   문서 전체에 흩어져 있으면 머리말·꼬리말 블록으로 봅니다. 실측(363쪽 Java 교안)에서
   `무단 사용/불법 배포/컨텐츠 자산/SK CC` 가 정확히 같은 35쪽에 나왔습니다.
   점수도 총 등장 횟수가 아니라 **몇 개 페이지에 걸쳐 나오는가**로 매깁니다.
3. **로컬 모델로 정제** — 코드 조각(`public static void main`, `int age`)은 규칙으로 거르기 어렵습니다.
   언어별 예약어 목록을 박으면 다음 교재가 파이썬일 때 무용지물이라, "강의에서 입으로 말할
   용어인가" 라는 판단만 모델에게 맡깁니다. **한글로만 된 용어는 모델이 지워도 되살립니다**
   (잘못 지운 것 대부분이 `부모 클래스`, `매개 변수` 같은 한글 개념어였습니다).
   Ollama 가 없으면 이 단계만 건너뜁니다.

과잉 필터링을 막는 가드가 셋 있습니다 — 30쪽 미만 문서는 2단계를 건너뛰고, 후보의 절반 넘게
지우려 하면 무시하며, 모델이 80% 넘게 지우면 규칙 결과를 씁니다.

용량 한계는 이렇습니다.

| 구간 | 한계 | 비고 |
|---|---|---|
| PDF 열기·텍스트 추출 | 사실상 없음 | 400쪽 / 4.3MB → 0.54초, 76,000자 |
| 업로드 | **64MB** | 넘으면 413 응답. `HTTPServer.maxBodyBytes` |
| 인식 힌트 용어 | **150개** | 더 넣으면 인식이 흔들립니다 |
| 요약 용어집 | 40개 | 프롬프트가 길어지면 녹취 요약이 밀려납니다 |

교안 **전문을 요약에 넣지는 않습니다.** Apple 내장 모델은 4K 컨텍스트에 아예 안 들어가고,
Ollama는 들어가더라도 녹취 요약을 밀어냅니다. 용어만 뽑아 쓰는 이유입니다.

**같은 교안은 두 번 분석하지 않습니다.** 파일 *내용* 해시로 결과를 캐시해 두어서, 이름을 바꿔 올려도 같은 파일이면 바로 붙습니다 — 실측 **26.5초 → 7ms**. 앱을 재시작해도 남습니다(`~/Library/Caches/ZoomCaption/domain`). 추출 규칙을 고치면 버전이 올라가 자동으로 무효화되고, **설정 → 교안 캐시 비우기** 로 직접 지울 수도 있습니다. 스캔본은 캐시하지 않습니다(OCR 후 다시 올릴 수 있어야 하니까).

**스캔 PDF(이미지만 있는 교안)는 용어를 못 뽑습니다.** 앱이 감지해서 알려줍니다 —
텍스트 레이어가 있는 PDF를 쓰거나 OCR을 먼저 돌리세요.

## 요약 품질

요약 엔진은 세 단계로 내려갑니다. 어떤 걸 쓰는지는 **요약** 탭 위에 표시됩니다.

| 엔진 | 컨텍스트 | 특징 |
|---|---|---|
| **Ollama (권장)** | 32K | 88분 강의를 **쪼개지 않고 한 번에** 요약. 약 85초 |
| Apple Intelligence | 4K | 쪼개서 요약하므로 앞뒤가 끊기고 전문 용어 환각이 잦음 |
| 추출식 | — | 모델 없이 원문 문장을 뽑음. 왜곡은 없지만 구조화 안 됨 |

같은 녹취로 비교한 결과입니다.

| 용어 | Apple 내장(~3B) | Ollama qwen3:8b | 녹취 원문 |
|---|---|---|---|
| 렐루 | "0보다 크면 1을 반환" ✗ | "양수 구간에서 기울기가 1" ✓ | 기울기가 1 |
| 패딩 | "데이터를 보호" ✗ | "가장자리에 0을 채워" ✓ | 0을 채우는 것 |
| 스트라이드 | "이동하는 속도" ✗ | "필터가 움직이는 간격" ✓ | 움직이는 간격 |

Apple 내장 모델은 4K 컨텍스트 탓에 map-reduce로 쪼개야 해서 강의 후반부가 통째로 빠지기도 합니다.

출력 형식은 모델이 아니라 **스키마로 강제**합니다(Ollama는 `format` JSON 스키마, Apple은
`DynamicGenerationSchema`). 그래서 `한 줄 요약 / 주요 내용 / 핵심 용어 / 과제·공지` 구조가
매번 동일하게 나옵니다. 공지·과제는 재요약을 거치지 않아 "다음 주 금요일 자정" 같은 기한이
사라지지 않습니다.

### 요약 범위 지정

기본은 **전체**입니다. 긴 수업을 나눠서 요약하거나, 앞부분을 이미 정리했다면 시작 지점을 지정합니다.

- **요약** 탭의 `요약 시작 지점` 에 `12:34` 또는 `1:02:03` 형식으로 적습니다.
- 자막의 **시각을 클릭**하면 그 시각이 자동으로 들어갑니다.
- 요약이 끝나면 마지막으로 훑은 지점이 표시됩니다. **이어서** 를 누르면 그 지점이 시작 시간으로 들어갑니다.

### 요약 따로 저장

요약만 별도 파일로 저장할 수 있습니다. 기본 위치는 그 수업 폴더, 기본 이름은 `제목_요약.md` 이고
둘 다 바꿀 수 있습니다. 전체 기록이 붙는 `transcript.md` 와 달리 요약만 들어갑니다.

### 모델 고르기

`OllamaClient.preferredModels` 순서대로 설치된 것을 자동 선택합니다.

```bash
ollama pull qwen3:8b     # 16GB RAM 권장 (약 5GB)
ollama pull qwen3:14b    # 24GB 이상
ollama pull qwen3:4b     # 8GB
```

### 메모리 — 요약할 때만 올라갑니다

메모리를 먹는 건 Ollama 서버가 아니라 **적재된 모델**입니다. 실측값입니다.

| | 메모리 |
|---|---|
| `ollama` 서버 프로세스 | 약 30~60MB |
| `llama-server` (qwen3:8b 적재 중) | **5,825MB** |

그래서 앱은 이렇게 동작합니다.

1. 요약을 누르면 Ollama 서버가 꺼져 있어도 **자동으로 띄웁니다** (`ollama serve` 를 직접 칠 필요 없음).
2. 요약이 끝나면 `keep_alive: 0` 으로 **모델을 즉시 내립니다.** 기본값인 5분 상주를 쓰지 않습니다.
3. 앱을 종료하면 앱이 띄운 서버도 같이 내려갑니다. 직접 띄워둔 서버는 건드리지 않습니다.

모델 재적재는 **1.7초**밖에 안 걸려서 붙들고 있을 이유가 없습니다.

Homebrew로 Ollama를 설치하면 로그인할 때마다 서버가 자동 실행되도록 등록될 수 있습니다.
`setup.sh` 가 이걸 꺼주지만, 직접 바꾸려면:

```bash
brew services stop ollama     # 상주 끄기 (앱이 필요할 때 띄움)
brew services start ollama    # 다시 상주시키기
```

모델이 아예 없거나 Ollama가 설치돼 있지 않으면 자동으로 Apple 내장 모델로 내려갑니다.

## 다른 사람에게 주기

`ZoomCaption` 폴더째 복사해서 주면 됩니다. 받는 쪽에서 `./setup.sh` 한 번.

`.app` 만 복사해도 실행은 되지만, **애드혹 서명이라 Gatekeeper가 막습니다**
(`spctl` 판정: rejected). 받는 사람이 아래 중 하나를 해야 합니다.

- `.app` 을 **우클릭 → 열기** → "열기" 확인 (처음 한 번만), 또는
- `xattr -d com.apple.quarantine ZoomCaption.app`

경고 없이 배포하려면 Apple Developer Program(연 $99)에 가입해 Developer ID로 서명하고
공증(notarize)해야 합니다. 그 전까지는 소스째 주고 `setup.sh` 로 각자 빌드하는 쪽이 깔끔합니다.

받는 사람 쪽 조건: **macOS 26 이상 + Apple Silicon**. 권한과 Apple Intelligence는 각자 켜야 합니다.

## 문제 해결

### 로그

앱은 실행·오류·주요 동작을 파일로 남깁니다. 이 앱은 Dock 아이콘이 없는 백그라운드 앱이라
터미널 출력이 어디에도 남지 않으므로, 문제가 생겼을 때는 이 로그가 사실상 유일한 단서입니다.

```
~/Library/Logs/ZoomCaption/zoomcaption-YYYY-MM-DD.log
```

**설정 탭 → 문제 해결** 에서 바로 볼 수 있습니다.

- **로그 보기** — 최근 400줄을 그 자리에서 확인 (오류는 빨강, 경고는 노랑)
- **로그 폴더 열기** — Finder 로 엽니다
- **진단 복사** — 환경·상태·최근 로그를 한 번에 클립보드로 복사 (문제 신고용)

시작할 때마다 환경을 한 번 통째로 기록합니다.

```
──────── ZoomCaption 시작 ────────
버전 1.0 (1)
macOS Version 26.5.2 (Build 25F84)
메모리 16GB, CPU 10코어
마이크 권한 미결정 (처음 마이크를 켤 때 물어봅니다)
mecab-ko /opt/homebrew/bin/mecab + mecab-ko-dic
Ollama 모델 qwen3:8b
```

**보관 기간은 14일**, 전체 20MB를 넘으면 오래된 것부터 지웁니다. 수업은 주 1~3회라
2주면 2~6회분이 남아 "가끔 그런다" 는 문제의 패턴을 보기에 충분하고, 그 이상 쌓아둬도
쓸 일이 거의 없습니다. 로그는 하루치가 수십 KB 수준이라 용량 부담은 없습니다.
바꾸려면 `Logger.retentionDays` 와 `Logger.maxTotalBytes` 를 고치면 됩니다.

### 앱이 안 켜질 때

**대개는 이미 실행 중입니다.** 이 앱은 Dock 아이콘도 창도 없어서 떠 있는지 알기 어렵습니다.
예전에는 그 상태에서 다시 실행하면 아무 일도 일어나지 않았지만, 지금은 **웹 UI 를 다시 열어 줍니다.**

그래도 안 되면:

- 브라우저에서 `http://127.0.0.1:8765` 를 직접 열어 보세요.
- 기본 포트가 다른 프로그램에 막혀 있으면 자동으로 8766~8769 를 시도하고, 어느 포트로 열렸는지
  로그에 남깁니다.
- 로그의 `[ERROR]` 줄을 확인하세요.

## 진단

```bash
# 오디오 권한과 무관하게 음성 인식 경로만 확인
say -v Yuna -o /tmp/t.aiff "안녕하세요. 오늘 수업을 시작하겠습니다."
./ZoomCaption.app/Contents/MacOS/ZoomCaption --selftest /tmp/t.aiff

# 교안 PDF 용어 추출만 확인
./ZoomCaption.app/Contents/MacOS/ZoomCaption --pdftest ~/Downloads/교안.pdf
```

실행 중에는 `http://127.0.0.1:8765/api/diag` 에서 탭 상태를 볼 수 있습니다 —
프레임 수, 무음 여부, **입력 레벨(피크 dBFS·RMS)**, 감지된 오디오 프로세스.
설정 탭의 문제 해결 섹션에도 같은 내용이 한 줄 판정으로 나옵니다.

**입력 정규화는 필요 없었습니다.** Core Audio 탭이 주는 레벨을 재보니
피크 **-2.5 dBFS**, RMS 0.109 로 이미 충분했습니다. 게인 보정을 넣으면 오히려 잡음만
키웁니다. 다만 Zoom 볼륨을 낮춰 두면 달라질 수 있어서, 레벨이 -30 dBFS 아래로 떨어지면
UI가 "볼륨을 올리라" 고 알려 줍니다.

## 실행 옵션

| 옵션 | 설명 |
|---|---|
| `--port 8765` | 웹 UI 포트 |
| `--locale ko-KR` | 인식 언어 |
| `--dir <경로>` | 세션 폴더들이 들어갈 기본 위치 |
| `--no-open` | 브라우저 자동 실행 안 함 |
| `--selftest <파일>` | 오디오 파일로 인식 경로만 검사 |
| `--pdftest <파일>` | 교안 용어 추출만 검사 (`--llm` 을 붙이면 모델 정제 전후 비교) |
| `--sumtest <파일>` | 녹취 텍스트로 요약만 검사 (`--pdf <교안>` 병용 가능) |

`open` 으로 실행할 때는 `open ZoomCaption.app --args --port 9000` 형태로 넘깁니다.

## 알아둘 점

- 탭은 `muteBehavior = .unmuted` 이라 캡처 중에도 소리는 평소대로 들립니다.
- 오디오 파일 자체는 저장하지 않습니다. 텍스트만 남습니다.
- 수업 녹음/녹취는 학교나 교수 정책상 사전 동의가 필요할 수 있습니다.
