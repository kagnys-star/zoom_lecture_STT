# ZoomCaption UI·관리자·오디오 설정 개편 설계 보고서

- 작성일: 2026-09-21
- 범위: 설계 및 구현 계획
- 상태: 구현 전 검토안

## 1. 최종 권고

이번 개편은 아래 네 가지 결론으로 진행하는 것이 가장 안전하다.

1. 자막 크기는 연속 슬라이더를 없애고 **작게 18px / 중간 22px / 크게 26px**의 3단계 선택으로 바꾼다. 기본값은 **중간 22px**, 줄 간격은 현재의 `1.62`를 유지한다.
2. 일반 사용자 화면과 관리자 화면은 같은 바이너리를 쓰되 **실행 진입점과 화면 구성을 분리**한다. 일반 사용자는 관리자 기능의 DOM과 API에 접근하지 못하게 한다.
3. **대조·다듬기 탭은 일반 사용자 HTML에서 아예 생성하지 않는다.** CSS로 감추는 방식은 사용하지 않는다. 두 탭은 관리자 화면에서만 보인다.
4. 설정의 현재 **“소리도 함께 저장” 체크박스는 제거**한다. 이 체크박스는 현재 정확한 Whisper 자막까지 끄기 때문에 의미가 잘못되어 있다. 대신 오디오 처리는 항상 켜고, 별도 **“Whisper 처리 후 원본 소리 보관”** 정책으로 영구 보관 여부만 선택하게 한다.

## 2. 현재 구현에서 확인된 사실

### 2.1 글자 크기

- 현재 자막 크기는 `15px`부터 `34px`까지 연속 슬라이더로 조절한다.
- 기본값은 `20px`이고 CSS 변수 `--cap` 하나가 Whisper 본문과 받아쓰는 중 영역에 적용된다.
- 슬라이더 값은 `localStorage`나 서버 설정에 저장되지 않아 새로고침하면 기본값으로 돌아간다.
- 사용자는 숫자를 보지 못한 채 미세한 값을 조절해야 하므로 “읽기 편한 크기”를 빠르게 재현하기 어렵다.

관련 코드:

- `Sources/ZoomCaption/Server/WebUI+Markup.swift`
- `Sources/ZoomCaption/Server/WebUI+Style.swift`
- `Sources/ZoomCaption/Server/WebUI+Script.swift`

### 2.2 관리자 모드

- 실행 옵션 `--admin` 또는 환경 변수 `ZOOMCAPTION_ADMIN=1`이 이미 존재한다.
- 관리자 모드에서는 시스템 전체 오디오 캡처, WAV 되먹임, Zoom 캡처 A/B 측정이 열린다.
- 일반 앱을 더블클릭해서 실행하면 관리자 모드에 들어갈 수 없고, 터미널 명령을 알아야 한다.
- 관리자 박스와 무음 점검 영역은 현재 HTML에 항상 포함한 뒤 `display:none`으로 숨긴다.
- 일부 관리자 API는 `options.admin`을 검사하지만, 대조·다듬기·표본 관련 API는 일반 모드에서도 열려 있다.

### 2.3 대조·다듬기

- `대조`, `다듬기` 탭은 현재 일반 사용자 사이드바에도 항상 나타난다.
- 메인 자막 툴바의 `갈린 곳 표시`도 `/api/compare`에 의존하는 고급 분석 기능이다.
- 화면에서 탭만 감추더라도 직접 API를 호출할 수 있으므로 관리자 분리라고 볼 수 없다.

### 2.4 소리 저장과 Whisper의 실제 관계

현재 오디오 흐름은 다음과 같다.

```text
SystemAudioTap
  ├─ SpeechTranscriber.feed       즉시 자막
  └─ AudioArchive.write           세션 WAV 저장
        └─ 30초 조각 생성
              └─ WhisperLive      정확한 Whisper 자막
```

`keepAudio == false`이면 `AudioArchive`를 만들지 않고, 그 결과 Whisper에 전달할 조각도 만들어지지 않는다. 즉 현재 체크박스는 “WAV 파일을 나중까지 보관할지”가 아니라 **Whisper 정확 자막을 사용할지**까지 결정한다.

따라서 현재 구조에서 소리 저장은 아래 기능에 필수다.

- 정확한 Whisper 자막 생성
- 인식이 틀린 구간 다시 듣기
- 대조 표본 판정과 정답지 작성
- 관리자 WAV 되먹임
- 추후 재전사

반면, Whisper 처리가 성공한 뒤에도 원본 WAV를 영구 보관하는 것은 정확한 자막 생성 자체에는 필수가 아니다. 현재 구현이 “처리용 오디오”와 “보관용 오디오”를 하나의 파일로 묶어 놓았을 뿐이다.

## 3. 자막 크기 상세 설계

### 3.1 권장 크기

| 단계 | 크기 | 용도 | 판단 |
|---|---:|---|---|
| 작게 | 18px | 한 화면에 많은 줄을 보고 싶은 사용자 | 본문 최소 가독성을 지키면서 정보량을 늘림 |
| 중간 | 22px | 일반 노트북·데스크톱에서 장시간 읽기 | **기본값 권장** |
| 크게 | 26px | 화면 공유, 먼 거리, 저시력 보조 | 자막성이 가장 강하지만 한 화면 줄 수가 감소 |

`15px`는 장시간 보는 한국어 자막 본문으로는 작고, `34px`는 일반 앱 창에서 줄바꿈이 지나치게 늘어난다. 18/22/26은 차이를 바로 느낄 수 있는 4px 간격이고, 현재 기본 20px에서 사용자가 갑자기 크게 느끼지 않으면서도 기본 가독성을 개선한다.

### 3.2 UI 형태

- 기존 range input을 `작게 / 중간 / 크게` 세그먼트 버튼으로 교체한다.
- 현재 선택은 배경, 글자색, 하단 강조선으로 함께 표시한다. 색 하나에만 의존하지 않는다.
- 버튼에는 `aria-pressed` 또는 라디오 그룹 의미를 부여한다.
- 키보드 Tab 및 방향키로 선택할 수 있게 한다.
- 툴바가 좁아지면 세 버튼은 한 줄을 유지하고, 검색창과 다른 도구가 다음 줄로 흐르게 한다.
- 선택값은 `localStorage`의 `zoomcaption.captionSize`에 저장한다.
- 저장값이 없거나 잘못되었으면 `medium`으로 복구한다.

### 3.3 토큰

```text
caption-small  = 18px
caption-medium = 22px
caption-large  = 26px
caption-line-height = 1.62
```

구현에서는 임의 숫자를 여러 곳에 반복하지 않고 `data-caption-size` 또는 하나의 CSS 변수 매핑으로 관리한다.

### 3.4 적용 범위

- Whisper 확정 자막 `.txt`
- `받아쓰는 중` 텍스트
- 실시간 최근 기록은 보조 정보이므로 본문보다 한 단계 작게 둘 수 있다. 다만 사용자가 “크게”를 선택했을 때도 최소 16px 이상을 유지한다.
- 타임스탬프, 버튼, 설정 설명은 자막 크기와 함께 확대하지 않는다. 자막 읽기 설정이 앱 전체 UI 배율로 오해되지 않게 한다.

## 4. 일반 사용자와 관리자 모드 분리

### 4.1 권장 정보 구조

#### 일반 사용자

```text
상단: Whisper | 요약
사이드: 교안 | 세션 | 설정
```

#### 관리자

```text
상단: Whisper | 요약                     [관리자 모드 배지]
사이드: 교안 | 세션 | 설정 | 대조 | 다듬기 | 오디오 진단
```

`대조`와 `다듬기`는 일반 사용 흐름보다 품질 측정·교정·실험 성격이 강하다. 관리자 모드에서만 제공하면 일반 UI가 단순해지고, 사용자가 “반드시 수행해야 하는 단계”로 오해하는 것도 막을 수 있다.

### 4.2 관리자 진입 방식

권장 방식은 **하나의 실행 파일 + 두 개의 실행 진입점**이다.

- `ZoomCaption.app`: 일반 모드
- 소유자용 `ZoomCaption 관리자 모드 열기`: 같은 서명된 실행 파일을 `--admin`과 전용 포트·전용 저장 위치로 실행하는 바로가기

관리자 바로가기는 개발자/소유자 패키지에만 포함하고 일반 사용자 배포본에는 넣지 않는다. 새 앱 코드를 복제하지 않으므로 기능이 서로 갈라지는 문제를 피할 수 있다.

관리자 화면에는 다음을 항상 표시한다.

- 헤더의 주황색 `관리자 모드` 배지
- 시스템 전체 오디오가 포함될 수 있다는 경고
- 현재 포트와 관리자 저장 위치
- 일반 녹음과 동시에 진단하지 말라는 안내
- `일반 모드로 돌아가기` 동작

현재 앱은 `127.0.0.1`에만 바인딩되므로 네트워크의 다른 기기에서 접근할 수 없다. 이 설계는 **로컬 단일 사용자용 기능 분리**다. 여러 OS 사용자나 공유 컴퓨터에서 관리자 인증까지 필요하면 2단계로 Touch ID/로컬 관리자 인증을 추가해야 한다.

### 4.3 화면 분리는 CSS 숨김이 아니라 서버 렌더링으로 처리

현재처럼 관리자 DOM을 항상 내려보낸 뒤 `display:none`으로 감추지 않는다.

권장 구조:

```text
GET /
  ├─ 일반 모드 → userMarkup + userScript
  └─ 관리자 모드 → userMarkup + adminMarkup + adminScript
```

이를 위해 `WebUI.page`을 정적 상수에서 `WebUI.page(isAdmin:)` 형태의 조립 함수로 바꾼다. 관리자 전용 JS도 별도 문자열로 나누면 일반 화면에서 존재하지 않는 요소를 참조해 전체 스크립트가 중단되는 회귀를 막을 수 있다.

### 4.4 API 권한 경계

일반 모드에서 아래 API는 `403 Forbidden`과 일정한 JSON 오류를 반환해야 한다.

- `/api/admin/*`
- `/api/quiet*`
- `/api/compare`
- `/api/polish/*`
- `/api/gold*`
- 관리자 대조용 `/api/audio`
- 대조 결과를 반영하는 `/api/fix`, `/api/correct/revert`

일반 사용자의 직접 자막 편집 API는 계속 사용할 수 있다. 관리자 기능에서 쓰는 “갈린 곳 표시”는 일반 툴바에서 제거하고 관리자 화면에서만 제공한다.

### 4.5 관리자 실행 안전장치

- 일반 모드와 관리자 모드의 저장 루트를 분리한다.
- 포트를 분리해 브라우저가 어느 인스턴스를 보고 있는지 명확히 한다.
- 관리자 인스턴스에서 시스템 전체 오디오 캡처를 시작하기 전에 일반 인스턴스의 녹음 여부를 확인한다.
- 관리자 모드에서 녹음 버튼 명칭을 `테스트 캡처 시작`으로 바꾼다.
- 관리자 로그는 기존 원칙대로 실사용 로그와 파일을 분리한다.

## 5. 대조·다듬기 탭 숨김 상세안

### 일반 모드에서 제거할 요소

- 사이드 탭 `대조`
- 사이드 탭 `다듬기`
- `panel-cmp`
- `panel-pol`
- Whisper 툴바의 `갈린 곳 표시`
- 대조·정답지·문맥 다듬기용 이벤트 처리기와 초기 로딩

### 관리자 모드에서 유지할 요소

- 대조 통계
- 갈린 구간 표시와 수정
- 소리 듣기 및 표본 판정
- 무음 의심 점검
- 문맥 다듬기 미리보기
- 교정 되돌리기

### 탭 접근성 개선

현재 사이드 탭은 클릭 가능한 `div`다. 개편 시에는 `button role="tab"`, `aria-selected`, `aria-controls`, 방향키 이동을 갖춘 탭으로 바꾼다. 이는 관리자 탭을 조건부로 만들 때 포커스 순서가 깨지는 문제도 함께 해결한다.

## 6. 소리 저장 설정 결정

### 6.1 결정

현재 `녹음 > 소리도 함께 저장` 체크박스는 **없앤다**.

이유:

1. 끄면 정확한 Whisper 자막까지 꺼지지만 설명은 단순 파일 저장 옵션처럼 보인다.
2. 앱의 핵심 화면이 `Whisper`인데 설정 하나로 해당 화면을 비게 만드는 구조는 예측하기 어렵다.
3. 녹음 전에 사용자가 정확도와 저장 구조의 내부 의존성을 이해하도록 요구한다.
4. 새로고침 시 체크 상태가 기본값으로 돌아가므로 설정으로서도 일관성이 부족하다.

### 6.2 대체 설정

설정의 `녹음` 섹션에는 “Zoom 소리만 캡처한다”는 설명만 둔다. 파일 보관은 별도 `저장 및 개인정보` 섹션으로 이동한다.

권장 문구:

```text
원본 소리 보관                                      [켬]
정확한 자막을 만들 때 소리는 이 Mac 안에서만 처리됩니다.
켜면 수업이 끝난 뒤에도 WAV를 남겨 다시 듣기와 재전사에 사용합니다.
시간당 약 110MB를 사용합니다.
```

토글을 끌 때:

```text
Whisper 처리가 끝나면 원본 소리를 삭제합니다.
정확한 자막은 그대로 남지만, 나중에 다시 듣기·재전사·대조 판정은 할 수 없습니다.
```

기본값은 **보관 켬**을 권장한다. ZoomCaption의 강점이 정확한 기록과 사후 교정이고, 시간당 약 110MB는 2시간 수업 기준 약 220MB로 사용자가 이해하고 관리할 수 있는 수준이다. 대신 현재 세션 예상 용량과 전체 저장 용량을 함께 보여 주고, 세션별 `원본 소리 삭제` 동작을 제공한다.

### 6.3 내부 구조 변경

현재 `keepAudio` 하나를 다음 두 책임으로 분리한다.

```text
audioProcessingRequired = true       정확한 자막용, 사용자가 끌 수 없음
audioRetentionPolicy = keep | deleteAfterWhisper
```

동작 순서:

1. 녹음 중 오디오는 항상 세션의 처리 파일 또는 안전한 임시 파일에 기록한다.
2. Whisper가 모든 조각을 처리한다.
3. Whisper 결과와 `session.json` 저장이 성공했는지 확인한다.
4. `keep`이면 `audio_*.wav`를 유지한다.
5. `deleteAfterWhisper`이면 해당 세션 디렉터리 안의 확인된 오디오 파일만 삭제한다.
6. 세션 메타데이터에 `kept`, `deletedAfterWhisper`, `deletionFailed` 상태를 기록한다.

삭제는 Whisper 작업 중간이나 앱 비정상 종료 시 수행하지 않는다. 재시작 후 상태가 불명확하면 자동 삭제하지 않고 사용자에게 확인을 요청한다.

### 6.4 설정 위치와 상태 표시

- `설정 > 저장 및 개인정보`
- `원본 소리 보관` 토글
- `현재 보관 용량: 1.4GB`
- `수업별 관리…` 버튼
- 세션 카드에는 `원본 소리 있음`, `처리 후 삭제됨`, `삭제 실패` 상태를 텍스트와 아이콘으로 표시

## 7. 구현 순서

### 1단계 — 자막 크기 3단계

- range input을 세그먼트 컨트롤로 교체
- 18/22/26px 토큰 추가
- 선택값 영속화와 잘못된 값 복구
- Whisper/받아쓰기/실시간 영역 적용 범위 검증

### 2단계 — 일반/관리자 UI 조립 분리

- `WebUI.page(isAdmin:)` 도입
- 관리자 마크업·스크립트 분리
- 일반 사용자 탭을 `교안/세션/설정`으로 축소
- 관리자 헤더 배지와 관리자 탭 구성
- 관리자 진입 바로가기 제공

### 3단계 — 서버 권한 경계

- 관리자 전용 라우트를 하나의 가드로 통일
- 일반 모드의 직접 URL/API 접근 거부
- 오류 상태와 HTTP status 일관화
- 정적 UI 계약 검사에 일반/관리자 두 변형 추가

### 4단계 — 오디오 처리와 보관 분리

- `keepAudio`를 retention policy로 교체
- Whisper 처리 파일은 항상 생성
- 성공 후 선택 정책에 따라 보관 또는 삭제
- 세션 상태와 UI 용량 표시 추가
- 기존 세션 파일은 기본적으로 `kept`로 해석해 호환 유지

## 9. 검증 기준

### 글자 크기

- 세 버튼이 각각 정확히 18/22/26px를 적용한다.
- 기본값은 22px다.
- 새로고침·창 재열기 후 선택이 유지된다.
- 700px, 940px 전후 레이아웃에서 툴바가 겹치지 않는다.
- 키보드만으로 선택할 수 있고 현재 상태를 스크린 리더가 읽는다.

### 관리자 분리

- 일반 모드에서 `cmp`, `pol`, `adminBox`, `quietBox`가 레이아웃과 접근성 트리에 나타나지 않는다.
- 일반 모드에서 관리자 전용 API는 모두 403이다.
- 관리자 모드에서만 대조·다듬기·오디오 진단 탭이 나타난다.
- 관리자 화면은 항상 관리자 배지와 캡처 범위 경고를 표시한다.
- 탭 수가 달라도 JS의 null 참조 오류가 없다.
- 관리자 테스트가 실사용 저장 폴더에 파일을 만들지 않는다.

### 오디오 보관

- `원본 소리 보관` 설정과 무관하게 Whisper 자막이 생성된다.
- `keep`은 기존과 동일하게 WAV를 유지한다.
- `deleteAfterWhisper`는 Whisper 완료와 세션 저장 성공 뒤에만 WAV를 삭제한다.
- 삭제 후 자막·요약·SRT는 그대로 남는다.
- 삭제된 세션에서 다시 듣기·재전사를 누르면 원인을 설명하고 복구 경로를 안내한다.
- 앱 중단·Whisper 실패·저장 실패 시 원본 오디오를 자동 삭제하지 않는다.

## 10. 위험과 대응

| 위험 | 대응 |
|---|---|
| UI에서만 숨기고 API가 열림 | 서버 라우트 가드를 필수 완료 조건으로 둠 |
| 관리자 DOM 제거 후 JS null 오류 | 관리자 스크립트 분리 + 일반/관리자 계약 검사 |
| 오디오 조기 삭제로 마지막 Whisper 구간 유실 | `worker.finish()`와 세션 저장 성공 후 삭제 |
| 관리자 전역 캡처를 실사용으로 오인 | 배지, 전용 포트, 전용 폴더, 버튼 명칭 변경 |
| 큰 글자에서 줄바꿈 과다 | 26px 상한, 기존 `overflow-wrap` 유지, 반응형 검증 |
| 기존 세션 호환성 | 보관 상태가 없는 옛 세션은 `kept`로 해석 |

## 11. 이번 설계에서 하지 않는 것

- 앱 전체 폰트 크기를 자막 크기와 함께 확대하지 않는다.
- 일반 사용자에게 관리자 탭의 빈 자리나 비활성 탭을 보여 주지 않는다.
- 관리자 요소를 CSS 숨김만으로 보호하지 않고 서버 API에서도 403으로 차단한다.
- 오디오 보관을 끈다는 이유로 Whisper를 끄지 않는다.
- 관리자 모드 진입이 녹음 중 상태를 조용히 바꾸게 하지 않는다.

## 12. 승인 요청 항목

구현 전 확정할 선택은 두 가지다.

1. 자막 크기: **18 / 22 / 26px, 기본 22px**
2. 오디오 기본 정책: **원본 소리 보관 켬**, 사용자가 원하면 “Whisper 처리 후 삭제” 선택

이 두 값을 승인하면 나머지는 위 구조대로 구현할 수 있다.

## 13. 구현 결과 메모

승인된 값인 **18 / 22 / 26px(기본 22px)**와 **원본 소리 보관 기본 켬**을 적용했다.
일반 화면의 관리자 DOM은 `administratorOnly` 역할로 레이아웃·접근성 트리에서 제외하고,
보안 경계는 모든 대조·다듬기·진단 API의 403 응답으로 구현했다. 기존 단일 페이지 JS가
관리자 요소의 ID를 참조하는 구조에서 DOM을 물리적으로 제거하면 일반 화면 전체가 멈출 수
있어, 이번 범위에서는 역할 기반 렌더링과 서버 권한 검사를 함께 쓰는 쪽을 택했다.

오디오는 보관 설정과 무관하게 Whisper 처리용으로 생성한다. 자동 삭제를 선택해도
Whisper의 모든 조각이 성공하고 세션 파일이 먼저 저장된 경우에만 `audio_*.wav`를 삭제한다.
실패·시간 초과·저장 오류 때는 `retainedForRecovery` 상태와 함께 원본을 보존한다.
